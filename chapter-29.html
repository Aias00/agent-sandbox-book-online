附录 A：答案与排错

练习参考答案

缩小图片通常需要读取指定图片、写入目标目录，以及有限的计算资源；不需要读取浏览器目录或连接邮件服务。实际工具可能需要预先安装依赖，这可安排在准备阶段。

自测 1：目录名不会改变进程的系统权限。自测 2：只读仅限制修改，读取与传输需要另外控制。自测 3：CPU 配额限制算力，超时限制持续时长。自测 4：绑定目录独立存在，通常继续保留。

自测 5：提示注入试图改变模型的决策，不可信代码在执行层产生动作，两者可形成“被骗后执行危险动作”的链路。自测 6：依据可信任务策略及用户授权范围，不能只凭模型请求。自测 7：程序可能输出错误内容、缺失文件或保留旧结果。自测 8：同时核对机制、权限、生命周期、数据处理、兼容性、运维和费用，并用自己的任务验证。

常见问题

“Cannot connect to the Docker daemon”：Docker 服务未启动、连接上下文不对，或当前用户无访问权。先检查 docker version 和 Docker 官方安装文档，不要直接给陌生脚本管理员权限。

“image not found”或拉取失败：先确认 docker pull 成功。控制器使用 –pull=never，是为了把网络准备与实际执行分开，避免运行时悄悄下载镜像。

“Permission denied”：看清路径在 /input、/output 还是其他位置。输入只读报错通常是预期；输出报错则检查宿主机目录权限、Docker 文件共享设置和用户映射。在启用 SELinux 的 Linux 上，还需按官方文档正确处理挂载标签，不要直接关闭主机安全机制。

“报告已存在”：为避免旧结果被误判，本书控制器要求你先手动移走旧报告。给不同实验使用不同目录也可以。

“任务超时”：记录打印出来的容器名，检查 docker ps -a。如果清理异常，可用 docker rm -f 后接这个确切容器名。不要复制会删除所有容器的批量命令。

“为什么我的平台结果不同”：Docker Desktop、Linux 内核、rootless 模式、企业策略和镜像版本都可能影响行为。记录差异并回到机制核对，比直接取消限制更能帮助定位。
