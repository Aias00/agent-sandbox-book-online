第 21 章：把同一个任务放进四项工程

E2B 兼容要拆成清单

“支持 E2B SDK”可以降低应用改动，但不代表每个 SDK 版本、模板格式、网络选项、文件接口、错误码和生命周期动作都完全一致。SPACE 的 ECW 文档还专门定义测试过的兼容范围：本次快照基线为 Python e2b 2.21.1 与 e2b-code-interpreter 2.6.2，不能据此宣称 JavaScript SDK 或所有版本已经验证；CubeSandbox 也有自己的扩展与部署规则。

迁移前写一份最小契约：能否创建和查询？执行输出如何返回？文件大小限制是什么？断流能否恢复？pause 保存了什么？delete 多久可确认？用你实际要用的 SDK 版本运行这些检查。

先不要做性能排行榜

启动耗时可能从收到 API 请求开始，也可能只测 VMM 创建；可能结束于返回 ID，也可能结束于客体里第一条命令完成。预热镜像、预启动 VM、快照恢复和真正冷启动都是不同条件。

建议测量“从应用发起请求，到得到经过校验的 250 报告”的完整耗时，并另外记录创建、就绪、执行、导出与清理。统计中位数和尾部延迟，同时记录错误率、并发、硬件和模板。只有同条件的测量才支持相应比较。

第一次选型可以很朴素

想学本地进程权限，优先读 sandbox-runtime；想从 Docker 走向服务 API，先研究 OpenSandbox；想深入 Firecracker 平台状态机，读 SPACE；想研究 RustVMM/KVM、网络和存储组合，读 CubeSandbox。这是阅读顺序建议，并不表示其他项目不能完成同类任务。
